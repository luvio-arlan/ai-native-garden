# 信任金字塔与代码库园艺实战手册

本手册整理自 Lauren Tan (`@poteto`) 在 AI Engineer CODE Summit 2026 的主题演讲 *《All Code Is Slop (Except Mine)》*，并结合生产级零容错工程实践，作为 `SKILL.md` 的深度参考。

---

## 1. 为什么“写好 Prompt / 扩充 AGENTS.md”必然失效

1. **注意力衰减与上下文稀释**：随着任务复杂度提升与上下文窗口膨胀，纯自然语言规范的遵从率非线性下降。
2. **代码库是 Agent 权重最高的真实上下文（Codebase as Memory）**：当 `AGENTS.md` 说“不要用 X”，但仓库里到处都是 X 时，Agent 几乎必然模仿现有代码继续写 X。
3. **人工 Review 无法对抗指数级代码供给**：当 AI 让生成代码边际成本趋近于零，瓶颈立刻转移到**验证与维护**。把人卡在逐行看 diff 上，只会陷入“低信任死循环”。

## 2. 纠错升级决策树（Error Escalation Ladder）

每次 Code Review、线上回归或测试失败暴露出 AI 犯错时，按下面 4 步定级：

```text
发现问题 / AI 犯错
   │
   ├─► 1. 能否重构 API / 目录边界，让错误在语法或可见性上“根本写不出来”？
   │       ├─ 是 → 改封装 / 缩小导出面（如私有化 DB 字段、收口唯一组件包装器）
   │       └─ 否 ↓
   ├─► 2. 能否写一条 Lint / depguard / 类型约束，在毫秒–秒级报出带修复指引的错误？
   │       ├─ 是 → 加规则 + 写清楚“替代方案是什么”的报错文案
   │       └─ 否 ↓
   ├─► 3. 能否补一条不变量测试 / Golden Parity / 契约漂移测试 / E2E 断言？
   │       ├─ 是 → 写入默认必跑门禁（确保零 skip、不靠手工白名单维护）
   │       └─ 否 ↓
   └─► 4. 仅限流程与协作约定（如发版顺序、沟通习惯）→ 以不超过 2 行写进 AGENTS.md
```

**铁律**：同一类错误出现第二次时，强制至少升到第 2 或第 3 级。

## 3. Error-Driven Lint 设计准则（替代“借口式注释”）

### 为什么要大幅削减非必要注释
- 过时注释会误导 Agent 做出错误推断。
- 解释“为什么这里绕过常规做法”的注释，会被 Agent 当作**逃生舱口（Escape Hatch）**，在新代码里继续照搬变通写法。
- **保留**：解释非显而易见的外部约束/协议/业务口径原因（`Why`），且优先把约束写进断言或测试名。
- **删除**：复述代码做了什么（`What`）、历史改动流水账、以及“注意千万不要在这里调用 X”这类本该由 Lint 拦截的提醒。

### 好坏报错文案对比

- ❌ 差的 Lint 报错：
  `Restricted import: defineAsyncComponent`（Agent 仍可能换种写法绕过或猜错替代品）
- ✅ 好的 Error-Driven 报错：
  `禁止直接使用 Vue defineAsyncComponent：请改用 @/versionGuard 的 safeAsyncComponent(...)，以确保发版后静态资源 404 时先暂存草稿再自动自愈刷新。`

## 4. 存量代码库的 Ratchet（棘轮）治理法

面对已有数万行代码的生产项目，切忌停下业务搞数周大重写；采用**棘轮策略**：

1. **新代码零容忍**：所有新增文件强制满足严格标准（如单文件行数上限、零 `watch` 滥用、零跨视图引用、零裸 SQL 穿透）。
2. **存量文件锁基线**：
   - 将存量超标文件写入白名单/基线清单（并记录当前行数或违例计数）。
   - 门禁要求：**允许维持或减少，严禁任何存量指标上涨**。
3. **顺手修剪（Boy Scout Rule）**：每次因业务需求改动某个巨型文件时，顺手抽离本次触碰的那一块职责（如一个 composable 或一个纯函数模块），并同步调低基线。

## 5. `AGENTS.md` 瘦身清单

建议每月或每个里程碑检查一次 `AGENTS.md`：

- [ ] 是否存在已在 Lint / CI / 门禁脚本里 100% 强制执行的细则？→ **删掉文档细则，只留门禁命令入口**。
- [ ] 是否存在重复解释业务细节或架构全貌的长段落？→ **移入 `docs/`，入口只保留 1 行索引链接**。
- [ ] 是否存在其他工具的规则副本（`CLAUDE.md`、`.cursor/rules`）？→ **删除副本，保持单一真源**。
- [ ] 全文是否能在 60 秒内通读完毕、零自相矛盾？
